# 《信以为真》概念设计文档

Nov 4, 2026 · @Purple

## 一句话概念

在一个“被相信的事物就会成真”的年轻世界里，你是一位不会老的人类旅人。你讲出的故事会在人们之间流传、变形，长成节日、地名和神灵，也长成你自己的传说；而旅途的终点，是回到那个一直在讲你故事的家。

## 设计支柱与核心情绪

核心情绪是惊喜与温暖：看到自己随口一句话在百年后长成了什么，忍不住笑出来。游戏不压抑，告别都以传承的方式延续。

- **讲述即玩法**：玩家最主要的动作是讲故事，而不是战斗、种地或送货。
- **意外的创造**：玩家能影响世界，但不能操控它。故事传开时会变形，结果总带着意外和喜感。
- **时间即成长**：时间流逝意味着世界在长大，而不是失去。
- **一条规则贯穿一切**：故事传播 → 被相信 → 成真。同一条规则创造神灵、点亮地图、塑造主角本人。

## 世界观

这个世界还很年轻，还没有被“讲完”。大地的大部分笼罩在雾中，雾不是普通的战争迷雾，而是还没有人讲述过的地方。

世界只有一条根本规则：口耳相传的东西，只要被足够多的人相信，就会成真。山神、河精灵、专门偷袜子的风精灵，都是从流言里长出来的。神灵的性格由传言塑造，会互相拌嘴、各有心愿，但世界里没有真正的恶。

文化基调是混合原创：东亚与欧洲的民间元素在这里自然交融，渔村挂着纸灯笼，麦田边立着风车，神灵既有山岳般的巨灵，也有小小的林间精灵。

主角是一位被祝福而不老的人类旅人。很久以前，旅人离开家乡，想去看看世界的尽头。醒来时已身在远方，回家的路隐没在雾里。旅人之所以不老，是因为各地流传着一个“永远年轻的旅人”的传说，而这个传说从何而来，是游戏最后的谜底。

## 核心规则：故事传播 → 被相信 → 成真

整个游戏只有一条规则在运转，它同时驱动神灵、地图和主角的成长。

每一次“成真”带来的新神灵、新土地和新能力，又成为下一轮故事的素材，循环越转越大。

## 主要系统

所有系统都是那一条根本规则的不同侧面，彼此咬合。

- **想法积木（输入）**：玩家从探索中收集词语和概念，拼成一个想法，例如“那座山 + 住着 + 会唱歌的巨人”。积木越收越多，本身就是收集要素；因为是结构化数据，NPC 能完全“理解”。
- **传播与变形（模拟）**：每个 NPC 有轻信、固执、健谈等属性和一张人际关系网。想法沿关系网扩散，每传一次可能按规则变形，像传话游戏。
- **文化沉淀**：传得够久的想法会逐级沉淀：流言 → 习俗 → 节日或地名 → 信仰。例如“会唱歌的巨人”三代后变成“山神春天要听歌”，村里多了春日歌会。
- **神灵诞生**：信仰达到阈值，神灵或精灵真的出现，性格取自变形后的版本。神灵会成为同伴、开路的钥匙和任务来源（他们的心愿）。
- **讲述即开图**：关于某片雾中土地的故事传开后，雾才散去，那里才真正成形。探索和讲故事是同一件事。
- **传言即能力（成长系统）**：没有经验值和技能树。人们相信你能做什么，你就能做什么，例如“旅人能和野兽说话”。奇怪的传言带来滑稽副作用，例如某地的猫都追着你跑。
- **称号**：借鉴荷马史诗里“足智多谋的奥德修斯”这类固定称谓。当下最流行的传言决定你的称号，NPC 会这样称呼你，比如“骑萝卜的旅人”。
- **吹牛**：你可以向吟游诗人讲自己的冒险，如实讲或添油加醋。夸张能换来更强的能力，但人们也会期待你兑现，带来新的委托。
- **吟游诗人**：传播能力最强的 NPC，可以结交、同行，是你“出版”故事的渠道。
- **冬眠与时间跳跃**：每到冬天旅人会在树洞里沉睡，一睡数年。醒来后的乐趣是看世界长成了什么样。
- **传承**：NPC 会老去，但家族世代记得你，信物和嘱托代代相传，关系不会断。

## 与分支剧情的区别

积木有限，但结果不是作者逐个写好的，而是模拟算出来的。分支剧情是作者事先写好一棵树，玩家只是挑路；我们更像乐高或语言本身，零件有限，组合与结果由系统生成。

- **同一句话，结果不同**：“会唱歌的巨人”讲给渔村，可能变成“海里的鲸神爱听歌”；讲给矿村，可能变成“山中巨人听着敲击声干活”；讲给固执的老人，故事可能就此断掉。结果取决于谁听到、在哪里、当地已经相信什么。
- **想法会互相作用**：村里若早已流传“雨水来自天上的湖”，两个流言可能融合成“巨人用歌声唤下天湖之水”，诞生的就不是山神而是雨神。分支树的分支互不影响，而这里每个想法都会改变下一个想法的命运。
- **玩家不能直接选结局**：分支剧情像点菜，这里像种花园。你选种子、土壤和浇水时机，长成什么要几年后醒来才知道。

粗略算一下：20 个名词、12 个关系、16 个修饰，能拼出的想法有 20 × 12 × 20 × 16 = 76,800 种，再乘上不同村庄、听众和已有信仰，作者不可能为每种情况写一个分支。

主线的归途和闭环结局仍由作者撰写，即**作者写骨架，系统长血肉**。主要风险是系统结果可能无聊或荒诞，所以原型第一步就是纯文字的传播沙盒，先验证它好不好玩。

## 变形规则的具体设计

变形由三部分决定：想法的数据结构、听众的属性、一组有限的“变形算子”。下面所有数值都是原型的初始调参值，需要在沙盒里反复调整。

### 想法的结构

每个想法 = 主体 + 关系 + 对象 + 修饰（可选），例如「巨人 · 住在 · 山 · 会唱歌的」。每块积木带三种标签：

- **领域**：山、水、风、天、火、林、人、兽，共 8 种。决定本地化的方向和神灵的模样。
- **基调**：敬畏、欢乐、恐惧、滑稽。决定它会被神化、变成节日，还是变成笑话。
- **升级链**：每个修饰有 2 到 3 级夸张版本，例如 会唱歌 → 歌声能唤雨 → 歌声能移山。

每个想法还有两个数值：**清晰度**（0 到 1，积木越多越低，越容易走样）和**信念覆盖率**（本村相信者占人口的比例）。

### 听众的属性

| 属性 | 取值 | 作用 |
| --- | --- | --- |
| 轻信 | 0–1 | 接受新想法的概率 |
| 固执 | 0–1 | 已有信念被改写的难度；高固执者转述更准确 |
| 健谈 | 0–1 | 每天转述给几个人 |
| 想象力 | 0–1 | 转述时发生变形的概率 |
| 职业 | 渔夫、矿工、农夫、织工、吟游诗人、商人、草药师、守庙人 | 决定职业滤镜的方向 |
| 年龄段 | 孩童、青年、中年、老年 | 孩童偏爱滑稽化，老人偏爱仪式化 |

每个村庄另有“文化底色”：环境领域（如渔村为水）、已有信仰列表和人口。

### 传播公式（每个游戏日）

1. 每个知道该想法的 NPC，按健谈值向关系网中的 1 到 3 人转述，关系越好越优先。
2. 听者接受概率 = 轻信 × 对讲述者的信任 × 契合度。契合度：与本地信仰相符为 1.2，冲突为 0.5，无关为 1.0。
3. 若听者已有冲突信念，改写概率再乘以 (1 − 固执)。
4. 每次转述的变形概率 = 0.1 + 0.4 × 想象力 + 0.3 × (1 − 清晰度)。触发时，从下表中满足条件的算子里挑一个。
5. 吟游诗人和商人会把想法带往别的村庄，这是跨村传播的主要途径。

### 变形算子

| 算子 | 触发条件 | 效果 | 例子 |
| --- | --- | --- | --- |
| 本地化 | 对象的领域不在本村环境中 | 换成本地同角色的事物 | 在渔村，巨人（山）→ 鲸（水） |
| 职业滤镜 | 听者职业与领域相关 | 按职业重新诠释关系 | 矿工把“唱歌”听成“敲击” |
| 夸大 | 基调为敬畏或欢乐，听者想象力高 | 修饰升一级 | 会唱歌 → 歌声能唤雨 |
| 神化 | 覆盖率高且基调为敬畏 | 生物变为神 | 巨人 → 山神 |
| 仪式化 | 关系为喜欢、需要或害怕 | 说法变成人们要做的事 | 山神喜欢歌 → 春天要为山神唱歌 |
| 融合 | 听者脑中另有共享领域或积木的想法 | 两个想法合并 | 巨人唱歌 + 天上的湖 → 巨人唱下天湖之水 |
| 人格化 | 主体是风、雨、梦等抽象事物 | 抽象事物变为精灵 | 风偷袜子 → 偷袜子的风精灵 |
| 滑稽化 | 听者是孩童，或基调为滑稽 | 修饰换成滑稽版本 | 庄严的巨人 → 爱打喷嚏的巨人 |
| 简化 | 想法超过 4 块积木 | 丢掉一个修饰 | 住在雪山顶会唱歌的巨人 → 会唱歌的巨人 |
| 反转 | 怀疑者转述，概率 2% | 关系取反 | 巨人爱听歌 → 巨人怕听歌 |

### 文化沉淀阈值

1. **流言**：本村至少 3 人相信。
2. **常识**：覆盖率达 30%，NPC 的日常对话开始提起它。
3. **习俗**：经过仪式化，且覆盖率 50% 持续 5 年。出现可见的行为，例如出海前唱歌。
4. **节日或地名**：习俗持续 15 年，或某地点被反复提及。地图上出现新名字，日历上出现节日。
5. **神灵诞生**：神化后的想法在至少 2 个村庄覆盖率达 60%。神灵的领域、性格、外观部件全部从这条想法的积木里读取。

信念也会衰退：没人再提起的想法，覆盖率每年下降。神灵需要被继续讲述，这也是神灵心愿任务的由来。

### 关于旅人的传言

主体为“旅人”的想法是一条独立轨道，决定主角的能力和称号。能力是**地区性的**，只在相信这条传言的地区生效：你在渔村是“能和海鸟说话的旅人”，到了矿村可能什么都不是。于是“去哪里、讲哪个故事”成了策略。

### 让变形可读、可控

- **传话链可追溯**：玩家能在织锦上看到一个想法如何一步步变成现在的样子，每一步是谁改的。随机感由此变成侦探式的乐趣。
- **玩家的杠杆**：挑选听众（健谈者传得快，固执者传得准，诗人传得远），亲自回去重讲以纠正，或者干脆利用变形。
- **兼容性表**：预先标注哪些积木能组合，过滤无意义的结果；每种算子都有预生成的文本模板。
- **混乱度上限**：每个村庄同时活跃的想法数量设上限，避免世界变成一锅粥。

## 成真的多种形态

被相信的东西不只会变成节日。它成真为什么，由想法里的**关系积木**决定，所以玩家选用哪个关系，就是在选择种下哪一类结果。

| 关系积木 | 成真为 | 例子 | 玩法意义 |
| --- | --- | --- | --- |
| 住在、藏在 | 生物或地点 | “湖里住着会说话的鱼”→ 湖里真的出现会说话的鱼；“云上藏着一座岛”→ 地图上出现浮岛 | 新的探索区域与 NPC |
| 能够 | 技能或技艺 | “矿村的人能听懂石头”→ 矿工学会找矿，村里产出新矿石 | 村庄的物产与贸易 |
| 来自 | 物品 | “雨水来自天上的湖”→ 雨天能收集到“天湖之水” | 收集品与交易品 |
| 守护 | 护身符或守护者 | “狐狸守护迷路的人”→ 出现狐狸护身符，持有者在雾中不会迷路 | 主角可用的道具 |
| 喜欢、需要 | 仪式与节日 | “山神喜欢歌”→ 春日歌会 | 定期事件与神灵心愿 |
| 害怕 | 禁忌 | “夜里吹口哨会招来风精灵”→ 真的会 | 规则、谜题与恶作剧 |
| 变成 | 自然现象与天气 | “春天的风会变成花瓣”→ 每年春天下花雨 | 天气与季节 |
| 帮助 | 动物伙伴或互助习惯 | “海鸟会帮渔夫找鱼群”→ 海鸟真的会引路 | 伙伴与效率 |
| 偷走 | 淘气精灵与小怪事 | “丢了的袜子都被风偷走”→ 偷袜子的风精灵 | 喜剧事件 |
| 唤来 | 召唤道具与仪式 | “敲三下铃铛能唤来雨”→ 出现雨铃 | 主角可用的工具 |

另外有两种跨类型的结果：

- **新词语**：流传足够久的说法会变成当地的谚语和问候语，并作为新的想法积木回到玩家手里。讲述本身会产出新的讲述材料，收集要素也因此源源不断。
- **人的特质**：关于一群人的传言会改变他们本身。“河谷镇的人走路特别快”传开后，那里的 NPC 真的更健谈，故事传得更快。

这些结果都遵循前面的沉淀阈值：先成为常识，再按关系类型成真。物品、技艺、禁忌等只需覆盖率 50% 并持续 5 年；神灵诞生仍然需要更高的门槛。为此，关系积木中的“跟随”替换为“能够”。

## 天气与季节

天气有晴、多云、雨、雷雨、雾、雪、风七种，加上由信仰产生的特殊天气，例如花雨、星雨、会唱歌的风。全部由代码实现：粒子、整体调色、环境声和角色动画，不需要为每种天气单独出背景图。

天气不只是氛围，它会影响传播：

- **雨天和雪天**：NPC 多待在家，故事在家人之间传得快，村与村之间传得慢。
- **晴天**：集市热闹，商人和诗人出门，跨村传播加快。
- **风天**：故事被“风带走”的概率提高，会随机落到邻村。风精灵也格外活跃。
- **雾天**：未讲述之地的雾更浓，但关于雾的故事更容易被相信。
- **季节**：春夏秋冬各有节日窗口和不同的物产；冬天旅人冬眠，一觉数年。

神灵也会影响天气。雨神诞生后会按自己的性格下雨，比如爱热闹的雨神偏偏在歌会那天下雨。玩家可以通过讲新的故事改变神灵的脾气，从而间接改变天气。

美术上只需 6 张粒子素材（雨丝、雪花、花瓣、落叶、雾丝、萤火），提示词见“美术提示词库”。

## 主线：归途（奥德赛的启发）

主线目标是回家。开放世界给了玩家自由，归途给了玩家方向和情感牵引。

《奥德赛》本身就是口传史诗，靠一代代吟游诗人传唱、每次都略有不同，这和我们的传播机制天然契合。书中最著名的冒险，又恰恰是奥德修斯在宫廷里亲口讲述的，有多少是真的无人知晓。我们从中借用五点：

- **回家的路由传说铺成**：家乡隐没在雾里。只有当关于你的传说传得足够远、传进家乡，回家的路才会出现。所以你越把故事讲开，离家越近。
- **帮倒忙的神**：像海神波塞冬一路阻挠奥德修斯，会有一位从你的玩笑里诞生的神灵（比如被你取笑过的“爱打喷嚏的海神”）一路捉弄你的航程。他是轻松的宿敌，可以在结局和解。
- **以讲述代替战斗**：大部分难关靠讲对的故事解决，而不是打败谁。
- **家中的织锦**：呼应佩涅洛佩织布等待，家乡的人世世代代把听到的关于你的传说织进一幅长卷。这幅织锦就是游戏的日志和图鉴界面，玩家能看到自己的传说在家乡被织成了什么样。
- **相认**：回到家时没人认得你，因为传说里的你和真实的你差太多（三米高、骑萝卜）。相认要靠只有真正的旅人才知道的小事。

## 闭环结局

开场与结局是同一个场景：一位奶奶在给孩子讲“永远年轻的旅人”的故事。玩家在结局才意识到，那个故事讲的就是自己。

**开场**：夜里，孩子缠着奶奶讲睡前故事。奶奶说：“很久很久以前，世界还没被讲完的时候，有一个永远年轻的旅人……”然后你在远方醒来，游戏开始。

**结局**：你终于回到家乡，站在那幅织锦前，又听见奶奶给孩子讲故事，讲的正是你的传说。这段传说由传播系统根据你的真实游玩记录生成，带着所有变形：你帮过谁、讲过什么、开过什么玩笑，都以夸张的样子出现在里面。每个玩家的结局都独一无二。

**最后的选择**：你可以亲口讲出一个“真实版本”，也可以让传说保持原样。两者都不悲伤，只是余韵不同。

这个结构同时闭合了三层：

- **因果**：你不老，是因为人们相信你的传说；你的传说，来自你的旅程。
- **情感**：离家开始，归家结束，是一次完整的奥德赛式回归。
- **玩法**：贯穿全程的核心机制，最终把玩家本人变成了神话。二周目里，NPC 可能隐约记得“好像在哪里见过你”。

## 灵感来源与差异化

单个元素都有前人，新意在于组合：玩家是讲故事的人而不是神，神从变形的流言里意外长出，讲述即开图，结局由玩家的游玩生成。

| 来源 | 借用了什么 | 我们的不同 |
| --- | --- | --- |
| 《奥德赛》 | 归途、口传史诗、亲口讲述的冒险、相认 | 回家的路由你的传说铺成 |
| 《葬送的芙莉莲》《Spiritfarer》 | 长寿者视角、温柔的情绪 | 时间流逝是成长与传承，不是失去 |
| 普拉切特《小神》、盖曼《美国众神》 | 信仰创造神灵 | 做成可玩的传播模拟，神的性格来自流言的变形 |
| 《上帝也疯狂》《黑与白》 | 信仰作为资源 | 玩家不是神，只能影响、不能操控 |
| 《Façade》 | NPC 理解玩家的话 | 用想法积木代替自由打字，规避海量语料 |
| 《星际拓荒》 | 闭环叙事 | 闭环由核心机制自然生成，而非预写 |

已放弃的方向：相对论太空快递（已有 Spacetime Delivery 等作品）、NPC 觉醒（子类型过于拥挤）。

## 技术方案与成本控制

运行时不调用任何 LLM API，玩家每多一个，成本不增加。方案是：结构化输入 + 规则驱动的传播模拟 + 开发期预生成的文本。

- **输入**：想法积木是结构化数据，不需要理解自由文本。
- **模拟**：传播、变形、沉淀、神灵诞生全部用普通代码实现，这是 Claude Code 最擅长写的部分。模拟核心写成独立于引擎的纯逻辑模块，方便单独测试和调参。
- **文本**：开发阶段用 AI 批量生成台词、传说、节日描述的变体，筛选打磨后存成数据文件；运行时按模板组合和查表。成本只在开发时付一次。
- **可选的后期功能**：让小型开源模型在玩家设备上本地运行，支持更自由的对话。代价是安装包变大、对配置有要求。
- **引擎**：网页优先，用 TypeScript + PixiJS 开发，浏览器直接玩；之后用 Capacitor 打包成 iOS 和 Android 应用，一套代码覆盖网页和手机。
- **美术**：用 GPT 生图制作插画素材，方案见“美术风格与分层方案”。

## 美术风格与分层方案

美术用 GPT 生图，风格为手绘绘本插画；全游戏约 395 张素材，组合和变化交给代码。完整提示词见“美术提示词库”标签页。

风格关键词：水粉与水彩质感、温暖柔和的色调、细腻的墨线、略带童趣的比例。世界是混合原创的民间传说风格，东亚元素（纸灯笼、织锦、木构屋檐）与欧洲乡村元素（石砌小屋、麦田、风车）自然交融，但不照搬任何真实文化的宗教符号。

### 三层做法

- **代码层，不需要新图**：季节与昼夜（整体调色）、雾（程序生成）、神灵的基调配色（滤镜）、NPC 服饰和家族信物的颜色（染色），以及所有习俗、地名、传言和能力文本。
- **组合层，少量部件拼出大量结果**：神灵 = 本体（8 领域 × 3 形态）+ 1 到 3 个环绕饰物 + 基调配色。饰物悬浮在本体周围而不是“穿戴”在身上，这样拼装不会错位。节日和城镇变迁由透明背景的道具叠加在场景上实现。
- **手绘层，精心挑选**：主角、5 位主线神灵、7 个区域的关键场景，每张多生成几版，挑最好的。

### 主角外观可选

提供 12 套预设外观（偏女性、偏男性、中性三种气质，各 4 种发型与肤色组合），每套 6 种表情。斗篷颜色由玩家在代码里自由调色。全身插画逐件拼装（纸娃娃式）在 AI 生图中很难对齐，所以采用整张预设图。

## 音乐与音效

Claude Code 不能直接作曲、输出音频文件，但它能写代码。所以音乐分三条线：成品曲目靠 AI 音乐工具或作曲人，音效靠免费素材库，动态播放和“会变形的歌谣”由 Claude Code 写代码实现。

- **成品曲目（14 首）**：用 AI 音乐生成工具（如 Suno、Udio 一类）或委托作曲人制作，全部为纯音乐。商用前务必确认所用工具的版权和使用条款。
- **音效**：从 Freesound、Pixabay、Mixkit 等免费素材库挑选，注意各自的授权要求，部分需要署名。
- **Claude Code 负责的部分**：动态音乐系统（按区域、时代、天气、昼夜淡入淡出和叠加音轨）；环境声的程序合成（风、雨、篝火可用 Web Audio 或 Tone.js 实时生成）；以及下面的“会变形的歌谣”。

### 会变形的歌谣

玩家教给村民的歌，本身也是一种想法。旋律在代码里是一串音符，每次转述都按变形算子改变：本地化换乐器（渔村用口哨和手鼓，矿村用敲击），夸大把旋律拉长、升调，滑稽化加入跳音，简化丢掉几个音。几十年后回来，你会听到自己那首歌的“当地版本”。它由 Tone.js 实时演奏，不需要任何录音，是整个游戏里最能体现核心机制的声音。

## 第一个原型的范围与里程碑

第一步只验证一件事：看着想法传播和变形，到底好不好玩。这一步不需要任何美术，纯文字版几天就能做出来。

1. **传播沙盒**：20 个 NPC 组成的小村，玩家输入想法积木，逐日观察它如何传播、变形、沉淀。
2. **时间跳跃**：冬眠数年后，生成一份“村子变成了什么样”的变化报告。
3. **神灵诞生**：某个想法达到信仰阈值时，生成一位性格来自变形版本的神灵。
4. **可走动的村庄**：加入地图、雾和“讲述即开图”。
5. **传言即能力**：实现第一个由传言获得的能力和称号。
6. **垂直切片**：一个区域、一位神灵、一次缩小版的归家闭环，可以拿给朋友试玩。

每个里程碑完成后亲手玩一下，不好玩就先改设计，再进入下一步。
